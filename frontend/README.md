# GEO Proof

一套自有、可运行的 GEO 监测与效果证明系统。它不把“监控报表”伪装成“优化引擎”，而是完整记录：客户问题 → 各 AI 平台运行 → 原始回答 → 品牌实体与引用 → 优化任务 → 发布 URL → 前后效果证据。

## 已完成范围

### 第 0 阶段：定义与口径

- [PRD](./docs/PRD.md)：目标用户、核心流程、页面与范围
- [系统架构](./docs/ARCHITECTURE.md)：采集层、解析层、证据层与产品层
- [指标字典](./docs/METRICS.md)：提及率、位置、情绪、声量份额、引用覆盖等公式
- [验收标准](./docs/ACCEPTANCE.md)：可追溯、一致性、异常与实体复核要求

### 第 1 阶段：监测底座

- 多客户项目与主品牌 / 竞品集合
- 提示词库、主题、意图、平台范围
- 运行队列与 `queued / running / parsed / failed / timeout / blocked` 状态
- 原始回答与解析结果分离保存
- 品牌位置、提及次数、情绪与来源 URL
- 失败重试、采集器拉取任务与结果回传接口

### 第 2 阶段：优化与证明

- 来源域名覆盖率与主品牌关联率
- 品牌别名候选、人工审批、历史回算审计事件
- 优化任务、负责人、目标平台 / 问题、发布 URL
- 发布前 / 后证据快照与按样本量加权对比
- 总览、平台、竞品、来源、运行和审计视图

## 本地运行

需要 Node.js `>=22.13.0`。

```bash
npm install
npm run dev
```

打开 `http://localhost:3000`。首次访问会自动建立本地 D1 数据表并注入两个演示客户项目。

## 验证

```bash
npm run lint
npm test
npm run db:generate
```

Drizzle 迁移位于 `drizzle/`；站点部署时使用名为 `DB` 的 D1 绑定。

## 接入真实采集器

系统提供一个与平台采集实现解耦的最小协议：

1. `GET /api/collector/next` 领取一个排队运行。
2. 采集器使用官方 API 或企业获准的浏览器自动化获得回答。
3. `POST /api/collector/ingest` 回传原始回答、耗时与引用。
4. 本系统解析品牌实体、保存证据并重新计算报表。

生产环境建议设置 `GEO_PROOF_INGEST_KEY`，采集器以 `Authorization: Bearer <key>` 访问。详细示例见 [采集器接入说明](./docs/COLLECTOR-INTEGRATION.md)。

## 产品边界

GEO 优化实际发生在客户自有网站、权威媒体、百科 / 行业资料与内容分发渠道；本系统负责发现机会、编排任务、监测 AI 平台是否采纳，并留下可以交付给客户的证据。平台账号、合法采集方式、生产调度器与客户内容发布权限需要在正式上线时配置。
