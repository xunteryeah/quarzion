## 已固化的发布保护

- `p0-production-preflight.sh` 会阻止 DNS、异地备份回执、核心密钥或镜像不完整的发布。
- 只有切换到 `resend` 模式时，发布才会强制实际发送一封测试邮件和一封测试异常通知；验证失败会直接终止。
- `deploy-p0.sh` 按“前置检查 → 扩展证书 → 完整备份 → 保存回滚快照 → 切换 → 验收”的顺序运行。
- 任一步失败会自动调用 `rollback-p0.sh`，恢复旧 Compose、Nginx、环境配置、旧镜像和旧数据卷。
- 内部邮件投递接口只允许容器内定时任务访问，公网固定返回 `404`。
- Nginx 访问日志把 `/invite/<token>` 记录为 `/invite/[REDACTED]`。
- 正式 Compose 按最小权限注入环境变量，管理端不会获得邮件供应商、采集器或告警密钥。

## 生产切换顺序

1. 明确设置 `QUARZION_EMAIL_MODE=queue_only`，门禁验证不得缺省绕过邮件。
2. 运行切换前完整备份，并再次执行恢复验证。
3. 部署正式镜像和统一数据库卷；旧两个数据卷保留但不再挂载。
4. 切换 Nginx，验证官网、客户后台、API 和管理员后台。
5. 激活队列、备份与健康检查计时器；队列在未配置 Resend 时不消耗重试次数。
6. 重跑跨组织、Cookie、限流、联系表单和回滚验收。
7. 后续配置 Resend 并真实验证后，将模式改为 `resend`。
