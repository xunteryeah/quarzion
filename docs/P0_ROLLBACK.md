# Quarzion P0 回滚手册

本手册用于 P0 迁移期间发生身份、权限、数据库或部署故障时恢复到已验证快照。

## 当前已验证快照

- 快照目录：`/opt/quarzion/backups/20260819T205841Z-p0-baseline`
- 校验：SHA256 全部通过。
- 数据库：前台和管理端备份均通过 SQLite `integrity_check`。
- 恢复演练：已在两个临时 Docker 卷中完成恢复并再次通过完整性检查。
- 配置：备份 Nginx 配置通过 `nginx -t`。

## 回滚触发条件

- 客户可以读取其他组织数据。
- 登录或权限故障影响全部客户。
- 数据迁移出现缺表、漏数据、重复数据或无法解释的指标变化。
- 新版本连续健康检查失败且不能在短时间内修复。
- 生产数据库不可用或迁移无法安全继续。

## 回滚前置动作

1. 明确目标快照目录，禁止使用“最新”软链接或模糊路径。
2. 执行恢复验证：

   ```bash
   /opt/quarzion/scripts/restore-verify.sh /opt/quarzion/backups/20260819T205841Z-p0-baseline
   ```

3. 对当前故障状态再执行一次 `backup-now.sh`，保留调查证据。
4. 记录回滚开始时间、操作者、原因和目标快照。
5. 暂停会产生写入的前台、管理端和 Worker；Nginx 可临时返回维护页。

## 恢复顺序

1. 停止前台、管理端和所有写入 Worker。
2. 将当前 `/opt/quarzion/frontend`、`/opt/quarzion/admin`、Nginx 配置和数据库卷归档为带时间戳的故障快照。
3. 在独立临时目录解包目标快照中的 `frontend.tar.gz` 和 `admin.tar.gz`。
4. 校验 `package.json`、Dockerfile、数据库迁移和目标配置均存在。
5. 恢复 `docker-compose.yml`、`nginx.conf` 和必要环境配置；环境文件权限必须保持 `600`。
6. 将目标数据库恢复到新建卷，而不是直接覆盖尚未归档的故障卷。
7. 对恢复后的数据库执行 `PRAGMA integrity_check` 和表级行数核对。
8. 重建前台和管理端镜像，并先在内部端口完成健康检查。
9. 执行 `nginx -t`，成功后再平滑重载 Nginx。
10. 验证官网、客户后台、管理端、API、旧域名跳转和 HTTPS。

## 回滚后验证

- 前台和管理端容器健康，重启次数没有持续增长。
- Nginx 配置测试成功。
- 快照数据库完整性为 `ok`，关键表行数与清单一致。
- `quarzion.com`、客户后台和管理端返回预期状态。
- 未登录请求不能进入受保护页面。
- 旧域名仍按预期 301 跳转。
- 新增一条回滚审计记录，并保存故障版本的日志和快照。

## 禁止事项

- 禁止在没有新备份的情况下直接覆盖生产数据库。
- 禁止对 Docker 根目录、工作区根目录或不明确的路径执行递归删除。
- 禁止回滚代码但保留不兼容数据库，或只回滚数据库不核对代码版本。
- 禁止因为页面能打开就宣布回滚成功；必须完成数据、权限、健康和域名验证。
